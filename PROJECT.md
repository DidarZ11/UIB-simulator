# UIB Simulator — описание проекта

Дипломный проект команды из трёх человек. Зафиксировано 30.09.2026 по итогам разбора идеи. Защита ориентировочно в конце апреля 2027 (около 7 месяцев, примерно по 10 часов в неделю на человека, всего около 900 человеко-часов).

## Что мы делаем

Веб-платформа UIB из двух частей:

1. **3D-кампус** в стиле low-poly. Студент ходит по университету, находит кабинеты, видит, кто из сотрудников где сидит.
2. **Система заданий.** Преподаватель создаёт тесты и задания, студент выполняет и сдаёт, преподаватель оценивает.

Пользователи: все студенты UIB и абитуриенты. Преподаватели работают в обычной веб-панели без 3D.

## Объём

### Входит

| Часть | Что именно |
|---|---|
| Кампус | 4 этажа, около 120 кабинетов. Камера от третьего лица, при приближении переходит в вид от первого (как в Roblox). |
| Сотрудники | Статичные NPC в кабинетах с карточкой: имя, должность, кабинет. |
| Панель студента | Дисциплины → задания → сдать. Кнопка «телепорт в кабинет». Это основной рабочий путь, 3D для него не обязателен. |
| Смысл 3D на каждый день | Маршрут до сегодняшней пары, квесты для первокурсников, кабинет дисциплины как место с её материалами и заданиями. |
| Панель преподавателя | Тест с автопроверкой, задание со сдачей файла, дедлайн, число попыток, список сдач, оценка, комментарий, выгрузка ведомости в Excel. |
| Админ-панель | Таблицы: кабинеты, сотрудники, дисциплины, группы. |

### Не входит (раздел «перспективы развития» в дипломе)

Мультиплеер, нативное мобильное приложение, автопроверка кода, таймер и перемешивание вопросов в тестах, достижения.

## Технические решения

- **Приложение:** Next.js + React Three Fiber. Сайт, панели и 3D живут в одном проекте.
- **Сервер:** Supabase (база данных, вход, хранение файлов). Размещение на Vercel. Начинаем на бесплатных тарифах; платим, только если бесплатные реально мешают.
- **Файл сдачи:** не больше 20 МБ.
- **Здание:** стены, полы и двери строятся кодом из JSON-файлов, составленных по фото схем этажей. Один кабинет добавляется записью в JSON.
- **Blender через ИИ (MCP):** только мебель (набор из 20–30 предметов) и 3–5 особых мест. Первое такое место — холл.
- **Загрузка:** один этаж за раз, переход по лестнице или лифту.
- **Телефон:** задания, тесты и сдача файлов работают через панель без 3D. 3D открывается в упрощённом режиме (без теней, меньше мебели) и отключается.
- **Язык:** русский. Все тексты интерфейса лежат в отдельных файлах, чтобы казахский и английский добавлялись переводом.

## Academo

Что известно: вход через учётную запись есть, данные вошедшего студента читаются, запись оценок, скорее всего, недоступна.

Как строим:

- Вход и роль (студент или преподаватель) берём из Academo.
- Оценки хранятся у нас. Преподаватель выгружает ведомость в Excel и переносит в Academo сам.
- Материалы дисциплины преподаватель прикрепляет в нашей панели вручную.
- Всё общение с Academo идёт через одну прослойку (адаптер). До получения доступа она работает на наших данных, потом подменяется настоящей без переделки остального.

## Что режем, если не успеваем

По порядку: мультиплеер (уже вне объёма) → 3D на телефоне → квесты → детализация кабинетов (остаются коробки с номерами).

Не трогаем: один полностью готовый этаж и цепочку «преподаватель создал → студент сдал → оценка видна».

## Риски

| Риск | Что делаем |
|---|---|
| Неизвестен объём доступа к API Academo | Бэкенд-разработчик за первые две недели получает в IT-отделе документацию и ответы. До этого работаем на адаптере. |
| Генерация здания из JSON может выглядеть плохо | Проба на первом этаже в первые две недели, решение на третьей. |
| Времени почти без запаса | Срез первого месяца покажет реальную скорость. Если он не готов к 31 октября, сокращаем объём сразу. |
| Данные реальных студентов в зарубежном облаке | Спросить в IT-отделе в том же визите, нужно ли согласование для пилота. |

## Вопросы к IT-отделу

1. Есть ли документация API Academo и тестовый доступ?
2. Как устроен вход через учётную запись Academo для стороннего приложения?
3. Какие данные читаются: роль, группа, дисциплины, расписание, сотрудники и кабинеты, файлы материалов?
4. Можно ли записывать оценку или факт сдачи?
5. Можно ли на время пилота хранить работы и оценки одной группы во внешнем облаке, или нужен сервер университета?

## Исследовательская часть диплома

- Сравнение с аналогами: Moodle, Gather, виртуальные туры вузов.
- Пилот на одной группе с одним преподавателем: число входов, число выполненных заданий, короткий опрос студентов и преподавателя.
